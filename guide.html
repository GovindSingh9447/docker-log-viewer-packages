User guide

Everything about DockBeacon — from first install to multi-host log merges, compose stacks, and power-user shortcuts. Written for v0.5.1.

Standalone + agent Logs + Stacks RBAC

Getting started

DockBeacon is a self-hosted web app that replaces juggling SSH sessions and docker logs commands. Install the package, open http://<host>:9447, sign in, pick containers, and stream. That HTTP URL is the supported zero-config path for lab and staging. Production puts TLS on a reverse proxy in front of the same port.

  1. Install the package Debian/Ubuntu or RHEL/Fedora — see the install page. 
    curl -fsSL https://govindsingh9447.github.io/docker-log-viewer-packages/install-apt.sh -o install-apt.sh
less install-apt.sh
sudo bash install-apt.sh
sudo apt-get install docker-log-viewer
  2. Configure the service Edit /etc/docker-log-viewer/docker-log-viewer.env, then enable systemd. 
    sudo nano /etc/docker-log-viewer/docker-log-viewer.env
# APP_MODE=standalone
# SERVER_NAME=my-host
# PROJECTS_DIR=/home/ubuntu/projects
# PORT=9447
# LISTEN_ADDR=0.0.0.0

sudo systemctl enable --now docker-log-viewer
  3. Open the UI & sign in Browse to http://<host>:9447. No TLS setup is required for lower environments. On first boot, a temporary password is printed in journalctl -u docker-log-viewer if you did not set AUTH_PASS. The login screen and header show the installed app version (for example v0.2.0) so you can confirm upgrades at a glance.
  4. Select containers → View logs Check one or more containers in the left sidebar, then click View logs. Press Start live to tail in real time.
Standalone vs agent. APP_MODE=standalone serves the full UI + API (your control plane). APP_MODE=agent is API-only on worker hosts — add agents in Settings → Servers and stream their logs from one browser tab.

UI tour

The interface has three main areas: header (server switch, health, role), sidebar (containers or stacks), and the main panel (logs or stack editor).

1
Header — product name with a quiet version beside it (e.g. v0.2.0), switch hosts, health, your RBAC role, refresh, theme, settings, logout.
2
Sidebar · Logs / Stacks — toggle modes. Logs lists Docker containers; Stacks lists compose projects under PROJECTS_DIR.
3
Container list — search, include stopped, bulk select (All / Running / Clear), then View logs.
4
Log toolbar — Start live, Pause, Fetch history, Inspect, Restart (operators), Clear, Copy, Download. Set time range and tail size.
5
Stats strip — per-container CPU % and memory with sparkline history while live.
6
Filter bar — text filter, log level, regex toggle, JSON pretty, wrap, font size, share link, full-window expand.
7
Log output — color-coded levels, container tags, clickable UUIDs/IPs, JSON blocks, filter highlights.
Missing version badge? Upgrade to v0.2.0+ (sudo apt-get install --only-upgrade docker-log-viewer or sudo dnf upgrade docker-log-viewer), then hard-refresh the browser. Version comes from the binary (GET /api/info) — a stale install can report an old package while still serving an older UI.

Viewing logs

Step 1 — Pick containers

Use the search box to filter by name, ID, or image. Enable Include stopped to see exited containers. Selected count appears above the list.

Step 2 — View logs

Click View logs (or press Enter when containers are checked). The header shows merged container names as chips — click a chip to mute that container’s lines in the stream.

Step 3 — Live vs fetch

  • Start live — WebSocket tail; reconnects automatically on drop.
  • Pause — freeze the stream without disconnecting (buffer keeps filling; resume to catch up).
  • Fetch — one-shot pull using tail size and time range (Last 15m / 1h / 6h / 24h / custom since-until).
Start livePauseFetchInspectClear Tail 500 · Last 1h
[api] GET /health 200 [worker] ERROR connection reset [api] {"level":"info","msg":"ready"}

Step 4 — Timestamps & auto-scroll

Toggle Timestamps to prefix each line. Auto-scroll keeps you at the bottom; when you scroll up, a ↓ New lines button appears.

Copy & download

Use Copy for the currently visible buffer, or Download to save a text file. Both respect active filters (muted containers and text/level filters).

Inspect & restart

Inspect opens a drawer with container JSON details. Restart is visible to operator and admin roles when a single container is active.

Filter & search

The filter box above the log output searches displayed lines. Press / anywhere (outside inputs) to focus it.

Plain text

Type any substring — matching text is highlighted in amber. Works on the full rendered line including container tags.

Regex mode (.* button)

Click the .* chip to treat the filter as a JavaScript regular expression. Invalid patterns show a toast and fall back safely. Regex preference is saved and included in share URLs (?regex=1).

Log level filter

The level dropdown filters by severity: Errors only, Warnings+, or Info+. Useful when a noisy service floods info lines but you need the failures.

Clickable tokens

UUIDs, container IDs, and IP addresses in log text are underlined — click to insert them into the filter instantly.

JSON highlighting

Structured JSON in log lines is detected automatically (brace-matched; Laravel-style [timestamp] prefixes are skipped).

Pretty vs compact

Toggle Pretty JSON in the filter bar:

  • On — indented block with syntax colors (keys, strings, numbers, booleans, null).
  • Off — inline compact highlighting without extra padding.
Pretty JSON.*Wrap
{
  "user": "admin",
  "status": 200,

Full-window mode

Click Expand in the filter bar (or press e) for a distraction-free view: only the filter strip and log output remain. Header, sidebar, stats, and main toolbar hide.

  • Connection status appears as a compact pill in the filter bar (live / paused / error).
  • Press Esc or e again to exit.
  • All filter controls (regex, JSON, wrap, font, share) stay available.

CPU & memory stats

When live streaming active containers, a stats strip appears below the log header. Each card shows:

  • Container name and current CPU % / memory usage
  • Mini sparklines for the last ~60 samples (fixed 0–100% scale so graphs stay comparable)

Cards update in place — no duplicate cards when stats refresh. Stats require Docker stats API access on the host.

Multi-host & groups

Architecture

Standalone (control plane)

APP_MODE=standalone on one host. Serves UI + API. This is where you browse containers and stacks locally.

Agent (worker)

APP_MODE=agent on other hosts. API only — no browser UI. Set CORS_ORIGINS to your control plane URL.

Add remote servers

  1. Open Settings (header) → Servers section.
  2. Add display name + URL e.g. http://10.0.1.5:9447, mode agent.
  3. Sign in when switching hosts — credentials are stored per server in your browser.
  4. Use the header dropdown to switch between standalone and agents.

Host groups

When adding a server, set an optional Group (e.g. Production). Servers with the same group name appear as a single merged entry in the server list. Selecting a group streams logs from all hosts in that group into one view — ideal when the same service runs on multiple machines.

Tip. Group names are case-sensitive after trim. Leave group empty for individual host entries.

Stacks mode

Switch the sidebar to Stacks to manage Docker Compose projects discovered under PROJECTS_DIR on the server. Requires operator or admin role for edits.

Tabs

TabPurpose
Compose YAMLEdit docker-compose.yml (or project compose file). Save creates a backup first; Diff shows changes before write.
EnvEdit .env. Secrets may be masked — toggle Reveal secrets to show values.
ImagesList local images, set IMAGE_NAME, pull new tags, then Compose up.
ConfigEdit allowlisted host files (nginx configs, etc.) configured on the server.

Lifecycle buttons

After selecting a project: Start, Stop, Restart, or Compose up. Status syncs in the header. Restore from timestamped backups via the backups dropdown.

Save shortcut in stack editor: Ctrl+S / ⌘+S.

Settings & RBAC

Open Settings from the header.

Password

Any signed-in user can change their own password (min 8 characters).

Roles

RoleCan do
viewerRead logs, inspect containers, switch servers
operatorEverything viewer + restart containers, edit stacks, compose lifecycle
adminEverything operator + manage users and roles

User management (admin only)

Create users with username, password, and role. Users are stored in the server’s users file (seeded from AUTH_USER / AUTH_PASS on first boot).

Security

Treat DockBeacon as a host admin console. Operator and admin roles can restart containers and edit Compose / .env files — not just read logs.

What is implemented

AreaBehavior
AccessHTTP via LISTEN_ADDR + PORT (lab: 0.0.0.0:9447). Production: LISTEN_ADDR=127.0.0.1 + reverse-proxy HTTPS.
LoginLocal bcrypt users and/or OIDC (OIDC_*). Login rate-limited per IP. AUTH_LOCAL=false disables passwords.
SessionHMAC cookie, HttpOnly, SameSite=Lax, COOKIE_SECURE=auto. Also X-Auth-Token / Bearer / Basic.
CSRFDouble-submit cookie dlv_csrf + header X-CSRF-Token on mutating cookie-auth requests.
RBACviewer / operator / admin. Inspect env secrets masked for viewers.
AuditJSON lines to journal + AUDIT_LOG_PATH. Admins: GET /api/audit.
AgentsOwn users file. CORS_ORIGINS required (fail closed). WebSocket Origin checked.
Service usersystemd User=docker-log-viewer, SupplementaryGroups=docker. Data under /var/lib/docker-log-viewer/.
DockerStandard Docker client env / socket. Optional docker-socket-proxy for blast-radius reduction.
PackagesGPG-signed apt/yum when CI has signing key; SHA256SUMS always published.

Still out of scope

  • In-process TLS — HTTPS stays on Nginx / ALB
  • SAML (use OIDC IdPs such as Keycloak / Authentik / Google)
Do not expose port 9447 to the public internet. http://<host>:9447 is for trusted networks (lab, staging, VPN). On production, set LISTEN_ADDR=127.0.0.1, put TLS in front, restrict agents to the control-plane network, and grant operator only to people you would give Docker socket access.

Production deployment

The process always speaks HTTP on :9447. That is intentional: zero-config for lower environments, HTTPS as a reverse-proxy concern in production.

Production layout: Internet → Nginx/ALB (TLS) → standalone control plane on 127.0.0.1:9447 → agents on private Docker hosts.

# /etc/nginx/sites-available/docker-log-viewer
server {
    listen 443 ssl http2;
    server_name logs.example.com;

    # ssl_certificate     /etc/letsencrypt/live/logs.example.com/fullchain.pem;
    # ssl_certificate_key /etc/letsencrypt/live/logs.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:9447;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
  1. systemd — sudo systemctl enable --now docker-log-viewer. Keep config in /etc/docker-log-viewer/docker-log-viewer.env.
  2. Firewall — allow 443 to the proxy. Allow control plane → agent :9447. Deny 9447 from untrusted networks.
  3. Agents — APP_MODE=agent, CORS_ORIGINS=https://logs.example.com, UI_URL=https://logs.example.com.
  4. Health — GET /health (Docker ping). Back up the users file.
  5. Upgrades — apt-get install --only-upgrade docker-log-viewer (env file is noreplace). Roll back from the package pool.

Share links

Click Share in the filter bar to copy a URL encoding your current state:

  • Selected container IDs (including group merges)
  • Active server / group
  • Filter text and regex mode
  • Live vs paused, tail size, timestamps, wrap, JSON pretty preference

Send the link to a teammate with access — opening it restores the same view (they still authenticate).

Configuration reference

Main environment file: /etc/docker-log-viewer/docker-log-viewer.env

VariableDescription
PORTHTTP listen port (default 9447). Lab/staging: http://<host>:9447. Production: reverse-proxy HTTPS to this port.
LISTEN_ADDRBind address. Lab default 0.0.0.0; production prefer 127.0.0.1 behind a reverse proxy.
APP_MODEstandalone (UI + API) or agent (API only).
SERVER_NAMEDisplay name in UI and logs.
COOKIE_SECUREauto (default), true, or false for the session cookie Secure flag.
PROJECTS_DIRRoot directory for compose projects (Stacks mode).
EXTRA_CONFIG_DIRSOptional allowlisted host dirs for the Stacks Config tab (e.g. nginx sites).
AUTH_USER / AUTH_PASSSeed admin on first boot only.
AUTH_LOCALSet false to disable password login (OIDC-only).
USERS_FILEPath to local users JSON (default under /var/lib/docker-log-viewer/).
AUDIT_LOG_PATHOptional audit log file path; admins can also use GET /api/audit.
OIDC_*Optional SSO: OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET, OIDC_REDIRECT_URL, OIDC_ROLES_CLAIM.
CORS_ORIGINSAllowed control-plane origins (required on agents; fail-closed when unset).
UI_URLRedirect target when hitting an agent root in the browser.

Installed paths

  • /usr/bin/docker-log-viewer — binary
  • /usr/share/docker-log-viewer/index.html — UI (standalone)
  • /lib/systemd/system/docker-log-viewer.service — systemd unit

Troubleshooting

Cannot sign in

Check sudo journalctl -u docker-log-viewer -n 50 for the bootstrap password. Verify USERS_FILE permissions if you customized auth.

Live stream disconnects

The UI auto-reconnects. If it loops, check reverse-proxy WebSocket support or firewall rules on port 9447.

Agent not listed / CORS errors

On the agent host set CORS_ORIGINS=http://your-control-host:9447 and restart. Add the agent URL in Settings with mode agent.

Stacks empty

Ensure PROJECTS_DIR points to a directory containing compose projects and restart the service.

OIDC login fails

Confirm OIDC_REDIRECT_URL matches the IdP callback exactly (including https). Check journal for OIDC errors after restart.

Stats missing

Stats need running containers and Docker stats access. Stopped containers show no sparklines.
