Security

Stacks and env edits are privileged

If this is reachable on a production network, a stolen session is more than log access — operators can restart containers and edit Compose / .env. Treat it like a host admin tool.

Authentication

Login required. Passwords stored as bcrypt hashes. Sessions are HMAC-signed cookies: HttpOnly, SameSite=Lax, Secure via COOKIE_SECURE=auto (honors X-Forwarded-Proto), 24h TTL. Optional OIDC SSO. Login rate-limited. APIs also accept X-Auth-Token, Bearer, or HTTP Basic.

RBAC

  • viewer — logs, switch hosts
  • operator — container inspect, start / stop / restart containers and PM2 apps, Compose lifecycle, env edits, reveal secrets
  • admin — operators plus user management, alert settings, and audit tail

Agents

Sign in once on the control plane. Agents trust that session when AUTH_SECRET matches. Agents still require CORS_ORIGINS (fail closed when unset). There is no second login when you switch hosts.

HTTP + reverse-proxy HTTPS

Lab listens on LISTEN_ADDR=0.0.0.0:9447 by default. Production: LISTEN_ADDR=127.0.0.1 and terminate TLS on Nginx/ALB. No in-process TLS.

Docker socket

Packaged unit runs as docker-log-viewer in group docker (not root). Socket access is still full Engine power — optionally put docker-socket-proxy in front and set DOCKER_HOST.

Secrets in .env / inspect

Stack env keys matching password / token / key names are masked until revealed. Container inspect is for operators and admins, with env secrets masked until revealed. Writes stay under PROJECTS_DIR.

Alerts & webhooks

Only admins change alert rules and channels, and every change is audited. Webhook URLs are stored server-side (0600) and never sent back to the browser, only a short hint. Slack, Teams, and Discord must use https://. Messages carry names and states, never log lines or env values.

CSRF / CORS / sessions

Double-submit CSRF (dlv_csrf + X-CSRF-Token) on mutating cookie-auth requests. WebSocket Origin checked against CORS_ORIGINS. Password changes require the current password.

Audit + packages

Privileged actions append JSON audit lines (AUDIT_LOG_PATH, also journal). Admins can GET /api/audit. Package repos are GPG-signed when GPG_PRIVATE_KEY is configured in release CI; otherwise SHA256SUMS + inspect-then-install.

Production

Deploy it like a host console

Same binary everywhere: HTTP on :9447. Lower environments open that URL directly. Production adds TLS at Nginx / ALB in front.

  1. Network isolationSet LISTEN_ADDR=127.0.0.1 in production. Agents should not be reachable from the public internet — only from the control plane.
  2. Nginx / ALB + TLSTerminate HTTPS on the proxy and forward to 127.0.0.1:9447. Enable WebSocket upgrade for /wslogs and /ws/project/watch. Set COOKIE_SECURE=auto.
  3. systemdRuns as docker-log-viewer (not root), group docker. Config: /etc/docker-log-viewer/docker-log-viewer.env. Data: /var/lib/docker-log-viewer/.
  4. FirewallAllow 443 to the proxy. Allow control-plane → agent :9447. Block 9447 from untrusted networks.
  5. Auth & backupsSeed AUTH_USER/AUTH_PASS only on first boot, or configure OIDC. Back up /var/lib/docker-log-viewer/. Optional: docker-socket-proxy to shrink Engine API surface.
  6. UpgradesCommands in Upgrade. Env file survives and the service restarts on its own (v0.6.5+). Roll back from the package pool.

Install

Ship it to your hosts

apt or dnf, configure once, enable systemd.

Upgrade

Run on each server (control plane and every agent). Your settings in /etc/docker-log-viewer/docker-log-viewer.env are kept.

Ubuntu / Debian (apt)
sudo apt-get update && sudo apt-get install -y --only-upgrade \
  -o Dpkg::Options::=--force-confold docker-log-viewer
sudo systemctl enable --now docker-log-viewer
sudo systemctl restart docker-log-viewer
Amazon Linux / RHEL / Rocky / Fedora (dnf or yum)
sudo yum update -y docker-log-viewer
sudo systemctl enable --now docker-log-viewer
sudo systemctl restart docker-log-viewer
Or re-run the installer (keeps current settings)
curl -fsSL https://dock-beacon.web.app/install.sh -o install.sh && sudo bash install.sh
Check it is running
systemctl status docker-log-viewer --no-pager
curl -s http://127.0.0.1:9447/api/info

Asked about docker-log-viewer.env during apt upgrade? Press N (keep your version). The --force-confold flag above answers it for you.
502 or "site can't be reached" after upgrading from v0.6.4 or older? Those packages stopped and disabled the service while upgrading. Run sudo systemctl enable --now docker-log-viewer. From v0.6.5 on, upgrades restart it automatically.
PM2 tab empty after upgrade? sudo apt-get install -y acl (or sudo yum install -y acl), then sudo /usr/lib/docker-log-viewer/pm2-grant-access.

One-step install

Ubuntu, Debian, Amazon Linux, RHEL, Rocky, Fedora. Detects apt, dnf, or yum.

Download, inspect, run
curl -fsSL https://dock-beacon.web.app/install.sh -o install.sh
less install.sh
sudo bash install.sh

Adds the repo, installs or upgrades docker-log-viewer, then asks: standalone (web UI) or agent (API for a control plane), server name, port, direct or behind nginx, and an optional URL prefix such as /dockbeacon. Agents also ask for the control plane URL and its signing secret. It writes the env file (keeping a backup), grants PM2 access when PM2 runs, starts the service, checks it answers, and prints the URL, the first admin password, and an nginx block when needed. Re-run it to upgrade; current settings are the defaults.

Unattended (agent example)
curl -fsSL https://dock-beacon.web.app/install.sh -o install.sh
sudo DLV_YES=1 DLV_MODE=agent DLV_SERVER_NAME=worker-1 \
  DLV_CONTROL_URL=https://logs.example.com \
  DLV_AUTH_SECRET='<control plane secret>' bash install.sh

Docker logs monitoring FAQ

Common questions about DockBeacon as a Docker log viewer and container monitoring tool.

What is the best self-hosted Docker log viewer?

DockBeacon is a lightweight self-hosted Docker log viewer and container monitoring tool. It streams live logs from many containers, shows CPU and memory metrics, and manages Compose stacks from one browser tab — without a SaaS account.

How do I monitor Docker container logs in real time?

Install DockBeacon with apt or dnf, open the web UI on port 9447, select containers, and start a live stream. Filter by regex or log level, and optionally merge logs across hosts with agents.

Can DockBeacon send Docker alerts to Slack, Teams, or Discord?

Yes. DockBeacon checks every host every 30 seconds and alerts when a container is unhealthy, exits unexpectedly, crash-loops, or nears its memory limit, when a PM2 app errors or restart-loops, when host CPU, memory, or disk stays high, or when Docker or an agent goes down. Alerts go to Slack, Microsoft Teams, Discord, or a generic JSON webhook. See the alerts guide.

Is DockBeacon a replacement for Loki or ELK?

No. DockBeacon is for live operations — what is happening on your Docker hosts right now. Loki and ELK are better for long-term log storage and analytics.

Does DockBeacon support multi-host Docker monitoring?

Yes. Run a standalone UI on one host and optional agents on others, then switch hosts or merge container logs and metrics in one console. One login covers every agent that shares AUTH_SECRET.

Can DockBeacon show PM2 logs?

Yes, on a host that already runs PM2. Logs shows a Docker / PM2 switch. Stdout and stderr stream in the same pane. Operators and admins can start, stop, or restart an app that is already in the list. Viewers can only read logs. DockBeacon does not start a PM2 daemon. After install, run sudo apt-get install acl and sudo /usr/lib/docker-log-viewer/pm2-grant-access so the service user can read those logs.
