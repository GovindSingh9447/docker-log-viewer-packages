Why not just docker logs?

It’s perfect — until your third SSH tab, second host, and first “wait, which terminal was prod?” moment.

docker logs

  • One container at a time, per host
  • Pipe to grep and start over when you get it wrong
  • JSON arrives as a wall of text
  • Separate window for docker stats
  • SSH into every machine

DockBeacon

  • Many containers, merged across hosts
  • Regex + level filters while streams keep running
  • Pretty JSON with syntax colors
  • CPU / memory charts next to the logs
  • One browser tab — UI + remote agents

Security

Stacks and env edits are privileged

If this is reachable on a production network, a stolen session is more than log access — operators can restart containers and edit Compose / .env. Treat it like a host admin tool.

Authentication

Login required. Passwords stored as bcrypt hashes. Sessions are HMAC-signed cookies: HttpOnly, SameSite=Lax, Secure via COOKIE_SECURE=auto (honors X-Forwarded-Proto), 24h TTL. Optional OIDC SSO. Login rate-limited. APIs also accept X-Auth-Token, Bearer, or HTTP Basic.

RBAC

  • viewer — logs, inspect (secrets masked), switch hosts
  • operator — restart, Compose lifecycle, env edits, inspect secrets
  • admin — operators plus user management and audit tail

Agents

Each agent has its own users file. Agents require CORS_ORIGINS (fail closed when unset). The control-plane UI signs in per host.

HTTP + reverse-proxy HTTPS

Lab listens on LISTEN_ADDR=0.0.0.0:9447 by default. Production: LISTEN_ADDR=127.0.0.1 and terminate TLS on Nginx/ALB. No in-process TLS.

Docker socket

Packaged unit runs as docker-log-viewer in group docker (not root). Socket access is still full Engine power — optionally put docker-socket-proxy in front and set DOCKER_HOST.

Secrets in .env / inspect

Stack env keys matching password / token / key names are masked until revealed. Container inspect env is masked for viewers. Writes stay under PROJECTS_DIR.

CSRF / CORS / sessions

Double-submit CSRF (dlv_csrf + X-CSRF-Token) on mutating cookie-auth requests. WebSocket Origin checked against CORS_ORIGINS. Password changes require the current password.

Audit + packages

Privileged actions append JSON audit lines (AUDIT_LOG_PATH, also journal). Admins can GET /api/audit. Package repos are GPG-signed when GPG_PRIVATE_KEY is configured in release CI; otherwise SHA256SUMS + inspect-then-install.

Production

Deploy it like a host console

Same binary everywhere: HTTP on :9447. Lower environments open that URL directly. Production adds TLS at Nginx / ALB in front.

  1. Network isolationSet LISTEN_ADDR=127.0.0.1 in production. Agents should not be reachable from the public internet — only from the control plane.
  2. Nginx / ALB + TLSTerminate HTTPS on the proxy and forward to 127.0.0.1:9447. Enable WebSocket upgrade for /wslogs and /ws/project/watch. Set COOKIE_SECURE=auto.
  3. systemdRuns as docker-log-viewer (not root), group docker. Config: /etc/docker-log-viewer/docker-log-viewer.env. Data: /var/lib/docker-log-viewer/.
  4. FirewallAllow 443 to the proxy. Allow control-plane → agent :9447. Block 9447 from untrusted networks.
  5. Auth & backupsSeed AUTH_USER/AUTH_PASS only on first boot, or configure OIDC. Back up /var/lib/docker-log-viewer/. Optional: docker-socket-proxy to shrink Engine API surface.
  6. Upgradesapt-get install --only-upgrade docker-log-viewer or dnf upgrade. Env file survives. Roll back from the package pool.

First boot
sudo nano /etc/docker-log-viewer/docker-log-viewer.env
# APP_MODE=standalone   # or agent
# SERVER_NAME=my-host
# PROJECTS_DIR=/home/ubuntu/backend
# PORT=9447

sudo systemctl enable --now docker-log-viewer
# lab / staging:  http://<host>:9447
# production:     https://logs.example.com  → proxy → 127.0.0.1:9447

standalone

agent

API only. Connect from a standalone UI.
